# PWM-LDCT v0.5 — Canonical dataset schema

This document is the **single source of truth** for the on-disk layout, the harmonized
record schema, and the loader contract of PWM-LDCT v0.5. The `pwm_ldct_loader` package
and the three preprocessing Dockerfiles (`pipelines/Dockerfile.{lidc_idri,aapm_2016,mayo_ldct_pd}`)
implement exactly this schema; the manuscript's *Methods → Cross-source harmonization* and
*Data Records* sections describe it in prose.

- **Schema version:** `0.5.0` (`MAJOR.MINOR.PATCH`; see *Data versioning* in the manuscript).
- **Companion specs:** [`dicom_cleaning_spec.md`](dicom_cleaning_spec.md) (de-identification),
  [`dicom_to_hdf5_mapping.md`](dicom_to_hdf5_mapping.md) (DICOM↔HDF5 tag/axis mapping),
  [`annotation_qa_protocol.md`](annotation_qa_protocol.md) (annotation QA loop).
- Values marked **[CONFIRM]** are pre-registered parameters to be ratified at release; they
  correspond to the manuscript's `\todo{}` markers and must match the manuscript at submission.

---

## 1. Sources and identifier scheme

Three public sources are harmonized under one schema:

| `source` value | Dataset | Real paired LD | Sinograms | Native annotations |
|---|---|---|---|---|
| `lidc` | LIDC-IDRI | no | no | 4-radiologist nodule XML |
| `aapm` | AAPM 2016 Low-Dose CT Grand Challenge | yes (r=0.25) | yes | none |
| `mayo` | Mayo LDCT-and-Projection-Data | yes (r=0.25) | yes | lesion labels on subset |

### 1.1 Identifiers

- **`patient_id`** — `{source}-{NNNN}`, e.g. `lidc-0001`, `aapm-007`, `mayo-042`. The numeric
  part is a stable, zero-padded re-index assigned in ascending order of each source's native
  de-identified subject ID. The mapping from native ID → `patient_id` is **not** published
  (it is a second de-identification layer; see [`dicom_cleaning_spec.md`](dicom_cleaning_spec.md) §5).
- **`series_id`** — `{patient_id}_{anatomy}_{role}`, where
  `anatomy ∈ {chest, abdomen}` and `role ∈ {fd, ld}` (full-dose / real-low-dose). Example:
  `mayo-042_abdomen_fd`. Simulated low-dose is **not** a separate `series_id`; it is stored as
  additional datasets inside the full-dose series' HDF5 file (§3).
- **`scan_uid`** — `sha256(series_id + schema_version)[:16]`, the stable content-addressable
  key used inside `manifest.sha256`.

### 1.2 Anatomy and modality

- `modality` is always `CT`.
- `anatomy` is derived from the source's `BodyPartExamined` plus a manual override table for
  mislabeled series (the override table is published at `schema/anatomy_overrides.csv`).

## 2. Release directory layout

The deposited release (PhysioNet DOI / Zenodo mirror) and any locally-regenerated tree share
this layout. Items marked *(local only)* are **regenerated by the pipelines** and not
redistributed (DICOM-derived pixels under restrictive DUAs); see *Data Records* in the manuscript.

```
pwm_ldct_v0_5/
├── schema/                         # these specification documents
├── pipelines/                      # Dockerfile.lidc_idri | aapm_2016 | mayo_ldct_pd
├── annotations/
│   ├── lidc_majority_vote/         # {patient_id}.json   (consolidated LIDC nodules)
│   ├── topup_aapm/                 # {patient_id}.json   (top-up nodules)
│   ├── topup_mayo/                 # {patient_id}.json
│   ├── likert/                     # {series_id}.json    (per-scan diagnostic Likert)
│   └── raw_per_reader/             # {patient_id}/{reader_id}.json
├── splits/
│   ├── train.txt  val.txt  test.txt          # one patient_id per line
│   └── split_assignment.csv                  # patient_id,source,anatomy,split,seed
├── sim_lowdose/
│   └── lidc/{patient_id}/{series_id}.h5       # deposited (LIDC is CC BY 3.0)
├── hdf5/                            # (local only) harmonized shards, all sources
│   └── {split}/{source}/{patient_id}/{series_id}.h5
├── metadata/{series_id}.json       # harmonized per-scan metadata (deposited)
├── manifest.sha256                 # sha256 of every released artifact
└── LICENSE/                        # per-artifact license texts (see Data Records table)
```

## 3. HDF5 layout (per scan)

One HDF5 file per **series** (`{series_id}.h5`). Compression: gzip level 4, per-slice chunking.
All image data are stored in **Hounsfield Units** (`float32`, after rescale slope/intercept and
the per-source HU offset correction; see §5.1). All arrays use C-order.

| HDF5 path | Shape | dtype | Units | Present for |
|---|---|---|---|---|
| `recon/full_dose`            | `[Z, H, W]` | float32 | HU  | all |
| `recon/low_dose_real`        | `[Z, H, W]` | float32 | HU  | `aapm`, `mayo` |
| `recon/low_dose_sim/r010`    | `[Z, H, W]` | float32 | HU  | all (sim at r=0.10) |
| `recon/low_dose_sim/r025`    | `[Z, H, W]` | float32 | HU  | all (sim at r=0.25) |
| `recon/low_dose_sim/r050`    | `[Z, H, W]` | float32 | HU  | all (sim at r=0.50) |
| `sinogram/full_dose`         | `[V, C, R]` | float32 | line integral | `aapm`, `mayo` |
| `sinogram/low_dose_real`     | `[V, C, R]` | float32 | line integral | `aapm`, `mayo` |

- **Axes.** Reconstructed volumes use `[Z, H, W]`: `Z` = slice (cranio-caudal, increasing
  `ImagePositionPatient[2]`), `H` = rows, `W` = columns. Projection data (DICOM-CT-PD) are stored
  in their **native, series-level layout** `[V, C, R]`: `V` = projection views over the helical
  acquisition (ordered by `InstanceNumber`), `C` = detector channels, `R` = detector rows. The
  projections are **not** per-reconstructed-slice — a helical view does not map to a single recon
  slice — so they are a series-level array, not indexed by `Z`. The fan-beam acquisition geometry
  (detector shape, channel count/positions, SID/SDD, pitch, views-per-rotation) is recorded in
  `metadata.geometry` (see [`dicom_to_hdf5_mapping.md`](dicom_to_hdf5_mapping.md) §3-§4).
- **Orientation.** Patient orientation is **preserved as released** (LPS, per DICOM
  `ImageOrientationPatient`). The pipeline does **not** reorient or flip.
- **Root attributes.** Every HDF5 file carries `scan_uid`, `patient_id`, `series_id`, `source`,
  `anatomy`, `schema_version`, and `metadata_sha256` (hash of the matching `metadata/{series_id}.json`)
  as HDF5 attributes for self-description.
- For full-dose-only sources (`lidc`), the `recon/low_dose_real` and `sinogram/*` groups are
  absent; the simulated-low-dose groups are always present.
- **Terminology.** `recon/low_dose_real` (and `low_dose_kind="real"` in §4) denotes the
  *source-distributed* reduced-dose. For AAPM/Mayo this is **Mayo's validated projection-domain
  noise insertion** applied to the real full-dose projections — **not** a second physical low-dose
  scan — as distinct from `recon/low_dose_sim/*` (this release's own forward-model simulation). The
  `_real` suffix is shorthand for *measured-reference* (vs. *our-simulation*), not "re-acquired".

## 4. Loader contract

```python
from pwm_ldct_loader import LowDoseCTDataset
ds = LowDoseCTDataset(root_lidc=..., root_aapm=..., root_mayo=...,
                      split="train", seed=42)
sample = ds[i]
```

`ds` indexes **per slice**. Each `sample` is a `dict` with the following keys:

| Key | Type / shape | Notes |
|---|---|---|
| `full_dose`    | `Tensor [H, W]` float32 | HU |
| `low_dose`     | `Tensor [H, W]` float32 | real where available, else simulated; see `low_dose_kind` |
| `low_dose_kind`| `str`                   | `"real"` \| `"sim"` |
| `dose_ratio`   | `float`                 | `0.25` for real; the requested `r` for sim |
| `sinogram`     | `None`                  | always `None` at the slice level — projections are series-level, not per-slice; use `get_series_projections` (below) |
| `has_projections` | `bool`               | whether series-level projection data exist for this `series_id` |
| `source`       | `str`                   | `"lidc"` \| `"aapm"` \| `"mayo"` |
| `patient_id`   | `str`                   | |
| `series_id`    | `str`                   | |
| `slice_index`  | `int`                   | `Z` index within the series |
| `annotations`  | `dict`                  | `{"nodules": [...], "likert": {...}}` (see §6) |
| `metadata`     | `dict`                  | parsed `metadata/{series_id}.json` (see §5) |

### 4.1 Loader arguments (harmonization knobs)

| Argument | Default | Effect |
|---|---|---|
| `split` | required | `"train"` \| `"val"` \| `"test"` |
| `seed` | `42` | propagated to Python / NumPy / PyTorch / CUDA RNGs; deterministic CuDNN |
| `dose_ratio` | `0.25` | which simulated ratio to surface when no real LD exists (`0.10`/`0.25`/`0.50`) |
| `prefer_real_ld` | `True` | use real low-dose when present, else simulated |
| `resample_spacing` | `None` | if set (e.g. `0.75`), resample in-plane to that mm spacing; default preserves native |
| `slice_thickness` | `"thin"` | `"thin"` selects ≤ 1.5 mm series; or a float mm target |
| `sources` | all three | restrict to a subset, e.g. `["aapm","mayo"]` for real-paired-only studies |

### 4.2 Series-level projections

Projection (DICOM-CT-PD) data are large and not slice-aligned, so they are accessed at the series
level rather than in the per-slice `sample`:

```python
proj = ds.get_series_projections(series_id)   # -> dict, or None if no projections
# proj["full_dose"]      -> ndarray [V, C, R] float32 line integrals
# proj["low_dose_real"]  -> ndarray [V, C, R] or None
# proj["geometry"]       -> dict (detector_shape, n_det_channels, n_det_rows, detector_channel_positions,
#                           source_to_isocenter_mm, source_to_detector_mm, pitch, views_per_rotation,
#                           vendor, calibration_status, raw_private_geometry)
```

`geometry` is also mirrored in `metadata.geometry` (§5). Fields whose exact semantics depend on the
collection's DICOM-CT-PD data dictionary are flagged via `geometry.calibration_status`.

## 5. `metadata/{series_id}.json` schema

One JSON object per series. Fields (✓ = always present; ○ = present where the source preserves it):

```jsonc
{
  "scan_uid": "string",                 // ✓
  "patient_id": "string",               // ✓
  "series_id": "string",                // ✓
  "source": "lidc|aapm|mayo",           // ✓
  "anatomy": "chest|abdomen",           // ✓
  "schema_version": "0.5.0",            // ✓

  "acquisition": {                      // per-scan scanner parameters
    "manufacturer": "string",           // ✓
    "model": "string",                  // ○
    "kvp": 120,                         // ○
    "exposure_mas": 0.0,                // ○  effective mAs (full dose)
    "pitch": 1.0,                       // ○
    "rotation_time_s": 0.0,             // ○
    "slice_thickness_mm": 1.0,          // ✓
    "pixel_spacing_mm": [0.0, 0.0],     // ✓  [row, col]
    "recon_kernel": "string",           // ✓  vendor kernel name, preserved (not re-reconstructed)
    "image_orientation_patient": [6 floats], // ✓
    "patient_position": "string"        // ✓  e.g. "HFS"
  },

  "calibration": {                      // harmonization corrections (do not alter raw pixels destructively)
    "hu_offset": 0.0,                   // ✓  per-source HU offset added (§5.1); 0.0 if none
    "mtf_50_lp_per_cm": 0.0,            // ○  measured per recon_kernel (manuscript Tech. Validation)
    "bowtie_profile": "measured|uniform_fallback", // ✓  uniform fallback flagged here
    "electronic_noise_sigma": 0.0       // ○  per-scanner σ_e used in low-dose sim
  },

  "lowdose_sim": {                      // parameters of the forward model (manuscript Eq. 1)
    "model": "pwm_core.contrib.modalities.ct_radon",
    "ratios": [0.10, 0.25, 0.50],
    "I0_monochromatic_ref": 0.0,        // per-scanner reference incident photon count
    "seed": 42
  },

  "demographics": {                     // aggregated from source headers; null where not preserved
    "age_years": null,                  // ○
    "sex": "M|F|null",                  // ○
    "bmi": null,                        // ○
    "scan_year": null,                  // ○  year only (Safe Harbor; see dicom_cleaning_spec §3)
    "indication": "string|null"         // ○
  },

  "provenance": {                       // for offline coordinate/parameter recovery
    "source_sop_class_uid": "1.2.840.10008.5.1.4.1.1.2",
    "rehashed_study_uid": "string",     // salted re-hash; see dicom_cleaning_spec §4
    "rehashed_series_uid": "string",
    "n_slices": 0,
    "deident_audit_id": "string"        // links to the de-id audit log row
  }
}
```

### 5.1 HU calibration

Pixels are converted to HU via the DICOM `RescaleSlope`/`RescaleIntercept`, then a per-source
constant `hu_offset` (measured from each source's published CT-performance-phantom data) is added
and recorded in `calibration.hu_offset`. Methods that need raw scanner HU can subtract it back.
`hu_offset` defaults to `0.0` and is **[CONFIRM]** per source at release.

### 5.2 Low-dose simulation

Simulated low-dose images are produced by the single forward model
`pwm_core.contrib.modalities.ct_radon` (manuscript Eq. 1: ray-dependent Poisson photon-counting
noise + additive electronic-noise floor) at `r ∈ {0.10, 0.25, 0.50}`, seeded by `seed` so the
realization is reproducible. The model is applied to **every** source's full-dose scan (including
AAPM/Mayo) so the simulated distribution is consistent; the AAPM/Mayo **real** low-dose is preserved
alongside for sim-vs-real comparison.

## 6. Annotation records (surfaced in `sample["annotations"]`)

Formats are defined normatively in [`annotation_qa_protocol.md`](annotation_qa_protocol.md) §7;
summarized here for the loader contract.

```jsonc
"annotations": {
  "nodules": [                          // per-slice subset of the series-level nodule list
    {
      "nodule_id": "string",
      "bbox_xyxy": [x0, y0, x1, y1],     // pixel coords in the slice's [H,W] frame
      "diameter_mm": 0.0,
      "texture": 1,                      // LIDC 1–5 texture scale
      "location": "string",
      "ground_truth": "majority_vote|adjudicated",
      "calibration_window": "string"     // provenance; see annotation_qa_protocol §6
    }
  ],
  "likert": {                            // per-scan, repeated on every slice of the series
    "reconstruction": "fbp|ir|tv",
    "dose_ratio": 0.25,
    "score": 3,                          // 1–5 diagnostic confidence
    "n_readers": 2
  }
}
```

`raw_per_reader/` preserves each reader's pre-consolidation labels in the same `nodules` shape,
keyed by `reader_id`, for uncertainty-aware downstream methods.

## 7. Splits and determinism

- Patients (never scans) are partitioned **60 / 20 / 20** train/val/test, **stratified by
  `(source, anatomy)`**. A patient's full-dose, real-low-dose, and simulated-low-dose data all
  reside in the same split.
- Assignment is deterministic given `seed = 42` and the `patient_id`:
  `bucket = (sha256(f"{seed}:{patient_id}") mod 100)` → `<60` train, `<80` val, else test, with a
  post-pass that guarantees ≥ 1 patient per `(source, anatomy)` stratum in every split.
- `splits/split_assignment.csv` records the final assignment and is itself hashed into
  `manifest.sha256`, so the split is frozen and verifiable.

## 8. Conformance

A tree conforms to schema `0.5.0` iff: (a) every `series_id` referenced in `splits/` has a
`metadata/{series_id}.json` validating against §5 and (where regenerated) an HDF5 file validating
against §3; (b) every HDF5 root attribute matches its metadata; (c) `manifest.sha256` verifies; and
(d) the de-identification audit ([`dicom_cleaning_spec.md`](dicom_cleaning_spec.md) §6) reports zero
unresolved PHI hits. The loader exposes `pwm_ldct_loader.validate(root)` which checks (a)–(d).
